Svara

On-device dictation, wherever you work.

Read case study ↗

Open source · Voice

Pythonfaster-whisperCTranslate2Windows APIsSQLiteOllama

The problem

Dictation needs to work inside the tools people already use. Transcription accuracy alone is not enough: clipped first words, lost recordings, duplicate text, or an accidental Enter in a terminal can make the tool unusable.

What I built

  • Connected microphone capture, a pre-roll audio buffer, local speech recognition, transcript cleanup, and text insertion into a system-wide Windows workflow.
  • Added streaming transcription, configurable CPU/CUDA inference, personal vocabulary, local history, and optional LLM cleanup.
  • Built tray controls, recording feedback, settings, packaged releases, and an update flow that waits for the user to restart.

Engineering decisions

  • Kept speech recognition on the device, with CPU support so the app does not require a dedicated GPU.
  • Made insertion aware of the target application: terminal-safe text handling, editor-specific paste behavior, and a clipboard fallback when Windows privilege boundaries block input.
  • Used temporary local recovery audio to protect unfinished dictation and removed transcript content from ordinary diagnostic logs. Optional cleanup depends on the configured model endpoint.

Evidence and current status

Released as an open-source Windows application. Recent commits repair recording lifecycle behavior and engine selection; the repository includes regression tests for cleanup, insertion, configuration, and log redaction. Its benchmark harness measures latency and transcription quality on the user’s hardware. Performance varies by model and device; this case study does not claim a universal speed or accuracy score.

Deep Researcher

Research you can trace back to its sources.

Read case study ↗

Personal · AI systems

PythonFastAPIPydanticSQLiteHTTPXpytest

The problem

A report can look well cited while its sources fail to support the actual claims. The engineering challenge was to preserve evidence throughout research and prevent unsupported material from reaching the final report.

What I built

  • Implemented a planner with bounded specialist workstreams, iterative searches, full-page and PDF extraction, and an adversarial review of missing or contradictory evidence.
  • Built a claim ledger containing source references, quoted passages, document locations, and provenance hashes.
  • Added SQLite checkpoints, cancellation and restart, live progress events, a REST API, a dashboard, and a command-line interface.

Engineering decisions

  • Separated exact-quote matching from model-based entailment checks: a quote must exist in the retrieved text, and the claim must be supported by that quote in context.
  • Selected passages relevant to each question instead of always truncating documents at the beginning.
  • Made the pipeline stop when evidence gates fail, while preserving diagnostics and rejected evidence for inspection. Search and model providers remain replaceable.

Evidence and current status

A working local research prototype with private source. Tests exercise persisted evidence, fabricated-quote rejection, document passage selection, URL boundaries, and PDF extraction using controlled fixtures and mocked services. Those tests verify pipeline behavior; they do not establish real-world factual accuracy or superiority to other research products. Live research still needs source review.

Ori no Michi

Learn origami through interactive 3D folds.

Read case study ↗

Personal · Interactive

TypeScriptReactThree.jsGSAPVinextPython

The problem

A static diagram often hides which layer moves, where it should land, and why a fold matters. I wanted learners to inspect a step from different angles, replay it, and pause while following along with real paper.

What I built

  • Implemented rigid polygon clipping and folding, layer selection, mountain/valley motion, unfolding, and turn-over steps.
  • Connected the engine to interactive lessons with crease guides, moving-flap highlights, alignment targets, orbit controls, and geometry-derived previews.
  • Built a tutorial theater with sequenced camera motion, chapters, scrubbing, captions, narration, playback speed, and a fold-along pause mode.

Engineering decisions

  • Selected moving layers using the authored crease segment so a fold on one flap does not move unrelated paper across the model.
  • Generated previews from the same geometry as the lesson to keep the visual explanation consistent with playback.
  • Used separate schematic checkpoints for complex workshops and provided reduced-motion behavior, keyboard controls, and device-local progress.

Evidence and current status

A private personal learning app. The source includes tests for paper-area conservation, finite coordinates, rigid edge lengths, layer selection, and tutorial chapter coverage. It also contains original narrated lesson films and caption files. The engine models rigid folds; it is not a general paper-physics or collision simulator, and complex workshop diagrams intentionally simplify hidden layers.

EstimateIO

A playful way to build an intuition for scale.

Read case study ↗

Personal · Interactive

TypeScriptReactVinextPointer EventsWeb Audio

The problem

Numbers alone make it difficult to judge size. I wanted players to learn by resizing an object beside a familiar reference, constructing a length, or placing an object on a scale.

What I built

  • Implemented three game modes: relative size comparison, making a measurement, and placement on a logarithmic size line.
  • Built pinch and drag controls with keyboard and button alternatives, unit selection, hints, streaks, and local best scores.
  • Made answer reveals overlay the guess and correct silhouette at a shared baseline so the error is visually understandable.

Engineering decisions

  • Stored canonical measurements in centimetres with explicit unit conversion and reference dimensions.
  • Scored proportional error symmetrically: guessing half the size and twice the size receives the same score.
  • Handled pointer addition, release, cancellation, and near-coincident fingers without sudden jumps or invalid scale values. Rotating challenge sets keep short runs varied.

Evidence and current status

A local personal browser game with private source. Logic tests cover score symmetry, conversions, logarithmic mapping, challenge rotation, and gesture transitions. References are attached to measurements; artwork is stylized and screen pixels do not represent life-size units. Its optional browser-tool integration is experimental and was not verified in a browser supporting that API.

Socratis

Live coding interviews combining WebRTC voice, a Monaco editor, and contextual AI feedback.

Read case study ↗

Public source · Prototype

Next.js 14PythonLiveKitDeepgramGroqMongoDBTypeScriptExpress

The setup

Candidate codes in Monaco. A Python voice agent drives the interview over WebRTC with LiveKit for transport, Deepgram for STT and aura-helios TTS, and Silero for voice-activity detection. The model is Groq's Llama-3.3 70B. Frontend is Next.js 14; an Express + MongoDB backend holds sessions.

Real-time code awareness

Earlier versions hallucinated about the candidate's code. V3's fix was Chat Context Injection: every edit in the Monaco editor pushes an explicit system message into the agent's context, so the model literally sees every diff instead of guessing.

Behavior rules

  • Socratic — hint, don't solve
  • Speaks only when detecting bugs, approach changes or stalls
  • Adapts to any coding problem; asks for a description when missing
  • Cross-references verbal claims against the code to catch overclaims

Post-interview forensics

The same agent runs a second pass after the call ends. Strict Big-O on time and space. Line-by-line bug fixes in "Line X: [Issue] → [Fix]" format. Communication analysis citing exact transcript quotes. A hallucination check cross-references the candidate's claims against their actual code. Output renders on a radar-chart result page.

Waldo

Multimodal PDF retrieval across text, tables, and figures, with query routing and retrieval review.

Read case study ↗

Public source · Prototype

PythonFastAPIReactViteQdrantLangGraphGeminiGroqDocling

The problem

Most RAG systems only handle text. Waldo is built for real-world docs where the answer might live in a table, bar chart or figure caption — research papers, medical reports, technical spec sheets.

Ingestion pipeline

  • IBM Docling extracts document structure with high fidelity
  • RapidOCR falls back for scanned pages
  • Gemini VLM transcribes figures to searchable semantic text
  • Sentence Transformers (all-MiniLM-L6-v2) embed chunks into Qdrant

Agentic retrieval

  • LangGraph routes between direct response and retrieval
  • Every retrieved doc gets LLM-graded for relevance
  • Failed queries are rewritten (max 2 retries)
  • Visual-query detection auto-includes figure transcriptions
  • Groq serves the final generation for low latency

Guardrails

Relevance checks and refusal instructions aim to keep answers grounded in the document. When vision-model quota is unavailable, ingestion can fall back to extracted captions. These controls reduce failure modes but cannot guarantee hallucination-free answers.

Current scope

An assessment prototype with in-memory retrieval and a single-document workflow. It demonstrates multimodal ingestion and retrieval orchestration; production persistence, multi-user isolation, and operational evaluation are outside this version.

Forge

A curated coding-agent workflow plugin with local activity logging and optional cross-session memory.

Read case study ↗

Public source · Prototype

Claude Code pluginNode.jsJSONLONNX embeddings

The problem

Power users of Claude Code accumulate a dozen overlapping skill packs, and a raw model has predictable failure modes: it assumes silently, over-builds, edits code it doesn't understand, and claims success it never verified. Forge is one namespaced lifecycle that enforces engineering discipline AND learns from your sessions so the agent stops repeating mistakes.

Falsifiable, not aspirational

  • tdd: no production code without a failing test first — watch it fail, delete pre-test code
  • debug: after 3 failed fixes, question the architecture
  • verify: a claim → required-proof table before 'done' is allowed
  • Each skill names the rationalization it forbids, so the agent can't talk itself out of the process

The memory loop

Four lifecycle hooks feed a zero-dependency Node core: every Edit/Write/Bash is logged as compact JSONL, a throttled background distiller (Haiku) extracts trigger → action lessons through a strict quality gate, and the highest-confidence lessons are injected at session start. Its memory subsystem was later extracted into a second standalone plugin, engram.

The code graph

forge:graph builds a static import graph for JS/TS, Python, C/C++, Ruby and Rust (including tsconfig aliases), surfaces god-nodes, cycles and dead files, and is rebuilt once then patched by an mtime-diff on every stop — a high-accuracy skeleton that stays cheap.

Branch and merge AI conversations while preserving the context of each path.

Public repository

The idea

Long chat sessions bloat LLM context. Every tangent and dead-end stays in history, burning tokens and diluting relevance. BranchGPT models the conversation as a Git-style DAG — every message is a node, forking spawns a parallel branch that inherits history up to that point, and merging is explicit.

Smart merging

  • Llama 3.3 summarizes branches before merging, so the parent only absorbs new insight — not the full branch transcript
  • Merge logic filters out shared history, appending only what's new
  • Merges recorded as distinct system events in the chat stream
  • The branch stays intact post-merge — you can keep exploring it

Tree navigation

A visual Git-tree sidebar renders the whole conversation graph. Click any node to jump. Each branch preserves its own history up to the fork point, so context switching is clean and unambiguous.

Stack

  • Next.js 16 — App Router + Server Actions
  • Neon Postgres via Drizzle ORM for tree storage
  • Vercel AI SDK wiring to Groq (Llama 3.3) for inference
  • Tailwind 4 + glassmorphic UI, full Markdown + LaTeX support

What it does

Point it at a GitHub URL or drag a folder in. MapMyRepo parses the tree, filters out noise (node_modules, .git, build artifacts), and renders it as a force-directed graph you can orbit, zoom, and drill into. The goal: understand complex architectures or onboard into unfamiliar codebases in minutes instead of hours.

Graph interactions

  • Scroll to zoom, drag to pan, click a node to select
  • Double-click a folder to expand or collapse its contents
  • Hover highlights connected nodes
  • Distinct icons and colors per file type + folder

AI layer (Gemini)

  • Per-node architectural summary generated on demand
  • Chat tab per node — "what does this file do?", "where is auth handled?", "explain the routing structure"
  • Contextual answers: Gemini sees the file / folder metadata + related nodes
  • Markdown-rendered responses via Marked

Import paths

  • Local upload: drag and drop any folder
  • GitHub URL: paste a public repo URL to visualize instantly
  • Optional GitHub PAT raises the 60/hr rate limit ceiling for private repos

Stack

  • React 19 + TypeScript + Vite 6
  • D3.js 7 for the force-directed graph
  • Google Gemini for per-node summaries and chat
  • Tailwind with glassmorphic sidebar + dark/light theming
