# Paper welcome and social sharing

The root portfolio uses the original `/old` split-shutter opening: VASU on the upper panel and DEVS on the lower panel. After a one-second word reveal, the two panels slide up and down over 1.5 seconds, with counter-moving type, exposing the portfolio underneath. Pale sage paper fades continuously into warm ivory across the two panels, matching the homepage. Smaller charcoal paper-cut letters use grain, slightly irregular edges, individual tilts and thin shadows. Both panels reuse the existing 73 KB WebP texture. The actual `/old` opening is unchanged. It runs on every document load and reload, including section URLs. Browser history restoration and reduced-motion visits skip it. Any page interaction dismisses it; the explicit Skip intro control also supports keyboard activation. Content is never locked or made inaccessible. Missing JavaScript or intro CSS leaves the portfolio usable.

Sound is on by default. The control now represents the user's preference, independently of AudioContext readiness. Browsers still require a trusted tap/click/keypress before audio can start. Explicitly muting persists across visits; choosing Test sound enables it again. The recorded keyboard samples, immediate hover scheduling and graph intensity behavior are retained.

`public/paper/assets/social-paper-v1.png` is the custom 1730×909 PNG sharing card, generated using the built-in image tool with the approved paper portrait and sage texture. See `social-card-prompt.txt` for the exact prompt. The source generated image remains outside the repository; the published file is an unchanged copy.

The root server HTML contains Open Graph image/title/description, actual image dimensions and alt text, plus Twitter's large-image card fields. The absolute image URL is public and versioned. No browser JavaScript is needed by a crawler. Future artwork changes should use a new filename to avoid stale image caches. Social platforms control whether and when they refresh or display their cached preview; a preview cannot be guaranteed on every mention. Reference: https://ogp.me/.

After building, run `node scripts/check-opening-sharing.cjs`, `node scripts/check-mobile.cjs` and `node scripts/check-production.cjs`, setting PLAYWRIGHT_MODULE if needed. The opening check uses one Chromium browser and a temporary loopback server, then cleans them up. It checks mobile/desktop scenery, dismissal, reduced motion, repeat reload behavior, direct project links, missing CSS/JavaScript, static card metadata and image headers, first-gesture audio and saved mute. Screenshots and its report are stored under `.cache/opening-qa/`. The mobile suite's Windows WebKit runtime has no Web Audio implementation; sound playback is verified in Chromium. This is emulation, not physical-device testing.
